# ADR-006: دورة حياة المستند — Draft → Posted غير قابل للتعديل؛ التصحيح بالعكس/المرتجع

- **الحالة:** Accepted — 2026-11-03
- **القرار المرتبط:** D-004
- **المتطلبات:** CH-N02 (عبدالكريم)، CH-F10 (منصور)، FR-SAL-006، FR-PUR-008، FR-ACC-010

## السياق
المالك لا يثق بتعديل الموظفين للفواتير بعد الطباعة. المعايير المحاسبية (SOX/رقابة داخلية) تمنع تعديل السجلات المرحّلة.

## القرار
1. حالات المستند: `draft` (قابل للتعديل، لا أثر) → `posted` (أثر على المخزون والحسابات؛ **غير قابل للتعديل أو الحذف**) → `reversed` (أُلغي أثره بمستند عكسي).
2. الترحيل **ذري**: المستند + الحركات + القيود + التدقيق في Transaction واحدة.
3. التصحيح = مستند جديد (`return_of_id` أو `reversal_of_id`) يتطلب صلاحية (`sales.return`, `documents.reverse`) — للمسؤول/المالك.
4. يُفرض بـ: Aggregate invariant + DB Trigger على `status='posted'` + Repository بلا `delete`.
5. الترقيم التسلسلي يُحجز عند الترحيل فقط (لا فجوات في المرحّل).

## البدائل المرفوضة
- السماح بالتعديل مع سجل: يفتح باب التلاعب ويعقّد المخزون/المحاسبة.
- الحذف الناعم للمرحّل: يكسر التوازن المحاسبي.

## النتائج
- ✅ ثقة المالك؛ أثر تدقيقي كامل.
- ⚠️ الكاشير يجب أن يراجع قبل الترحيل → تأكيد واضح في الواجهة + إمكانية "تعليق" قبل الترحيل.

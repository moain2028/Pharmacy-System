# تصميم المحاسبة (Accounting Design) — PostingRules بأمثلة رقمية

> **المرجع:** ADR-007, ADR-008, DATA-MODEL §2.8/§4. كل قاعدة هنا = دالة في `packages/domain/accounting/PostingRules.ts` + اختبار Unit.
> **الاصطلاح:** المبالغ بالريال اليمني (minor = ريال). الرموز: `Dr` مدين، `Cr` دائن. كل قيد يجب أن يتوازن.

---

## 1. المبادئ
1. **لا يرى الكاشير مديناً/دائناً.** كل مستند يولّد قيده تلقائياً.
2. **Anglo-Saxon:** الشراء يزيد المخزون (أصل)؛ البيع يسجل الإيراد **و** تكلفة البضاعة المباعة بتكلفة الدفعة الفعلية.
3. **Immutable:** العكس بقيد جديد `reversal_of`.
4. **العملة الأساسية** للدفاتر؛ المعاملات بعملة أخرى تُحوَّل بسعر اليوم ويُخزَّن السعر في كل سطر.

## 2. قواعد الترحيل (Posting Rules)

### PR-01 بيع نقدي
مثال: فاتورة 3 أصناف إجمالي **4,500**، خصم **200**، صافي **4,300**، تكلفة الدفعات المخصصة **2,900**.
| حساب | Dr | Cr |
|---|---|---|
| 1100 الصندوق | 4,300 | |
| 4120 خصومات ممنوحة | 200 | |
| 4100 المبيعات | | 4,500 |
| 5100 تكلفة البضاعة المباعة | 2,900 | |
| 1400 المخزون | | 2,900 |
| **المجموع** | **7,400** | **7,400** |
> الربح الإجمالي للفاتورة = 4,500 − 200 − 2,900 = **1,400**.

### PR-14 فتح/إقفال وردية
- الفتح: لا قيد (النقد موجود أصلاً في 1100). يُسجل `opening_cash` كمعلومة.
- الإقفال مع فرق: إن `counted < expected` بفرق 500:
| 5530 مصروفات أخرى (عجز صندوق) Dr 500 | 1100 الصندوق Cr 500 |
  (والعكس للزيادة إلى 4300 أو حساب مخصص).

### PR-17 عكس قيد (Reversal)
أي قيد يُعكس بقيد جديد بنفس الأسطر مع تبديل Dr/Cr و`reversal_of_id` = الأصل. يُستخدم عند عكس مستند كامل.

## 3. التقارير المشتقة
| التقرير | الصيغة |
|---|---|
| **ميزان المراجعة** | لكل حساب: Σdebit, Σcredit, الرصيد |
| **الأرباح والخسائر** | الإيرادات (4xxx) − المصروفات (5xxx) للفترة |
| **مجمل الربح** | المبيعات − المرتجعات − الخصومات − COGS |
| **الميزانية المبسطة** | الأصول = الالتزامات + حقوق الملكية (+ صافي الربح) |
| **قيمة المخزون** | من `stock_balances × lots.unit_cost` ويجب أن تساوي رصيد 1400 (اختبار تطابق يومي) |
| **كشف حساب عميل/مورد** | أسطر 1300/2100 مفلترة بالطرف |
| **أعمار الديون** | تجميع الذمم المفتوحة حسب 0–30/31–60/61–90/>90 يوم |
| **التدفق النقدي المبسط** | حركة 1100/1200 مصنفة (تشغيلي/مصروفات) |

## 4. اختبارات الاتساق (Invariants Tests — تُنفَّذ ليلياً وعند الطلب)
1. `Σ journal_lines.base_debit = Σ base_credit` لكل entry.
2. رصيد 1400 المخزون = Σ(`stock_balances.on_hand × lot.unit_cost`) ± تقريب.
3. Σ ذمم العملاء (1300) = Σ(فواتير آجلة مفتوحة − تحصيلات).
4. كل `sales_invoice posted` له journal_entry واحد (أو عكسه).
5. كل `stock_movement` بنوع sale/purchase له مستند مرحّل.
6. `stock_balances` = إعادة بناء من `stock_movements` (تطابق تام).

## 5. التقريب والتوزيع
- خصم الفاتورة يُوزَّع على الأسطر بـ Largest Remainder لحساب `line_total` و`cogs` الدقيقين للتقارير حسب الصنف؛ القيد يستخدم الإجماليات.
- `Money.allocate(total, weights[])` مُختبَر: Σ الأجزاء = الكل دائماً.

## 6. ما يحتاج تأكيداً من العميل/الفريق
- سياسة البونص (`zero_cost` افتراضي).
- هل خصم الشراء يخفّض التكلفة (افتراضي نعم) أم يُسجل كإيراد؟
- حساب عجز/زيادة الصندوق (افتراضي 5530/4300).

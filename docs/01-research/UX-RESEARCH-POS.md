# R9 — بحث تجربة المستخدم لنقاط البيع والصيدليات

> **الهدف:** (طلب معين) هيكلية واجهات وأزرار سهلة وسهلة التعلم للمستخدمين البسطاء. نستخلص المبادئ من أنظمة POS الناجحة ومعايير WCAG/Nielsen وواقع الصيدليات اليمنية.

---

## 1. دروس من الأنظمة الناجحة
| النظام | الدرس |
|---|---|
| **PioneerRx** (الأعلى رضا في استطلاعات الصيادلة الأمريكيين) | شاشة واحدة لأغلب العمل، اختصارات لوحة مفاتيح لكل شيء، تحديثات مبنية على ملاحظات المستخدمين، دعم ممتاز [1] |
| **Square POS / Loyverse** | أزرار كبيرة، بحث فوري، سلة واضحة، إتمام البيع بضغطتين، يعمل على اللمس والفأرة |
| **Odoo POS** | وضع ملء الشاشة بلا تشتيت؛ لوحة أرقام مدمجة؛ يعمل أوفلاين ويزامن |
| **بديل سوفت (محلي)** | يروّج صراحة لـ "مفاتيح اختصارات في مختلف الشاشات" و"سهولة التنقل" — السوق المحلي يقدّر هذا [2] |
| الأنظمة القديمة (QS/1 سابقاً) | الواجهات القديمة = إحباط وبطء — سبب هجرة العملاء [1] |

## 2. المبادئ المعتمدة (Design Principles)
1. **شاشة البيع = مركز الكون.** 90% من وقت الكاشير فيها. تُفتح مباشرة بعد الدخول.
2. **الفأرة اختيارية.** كل عملية بيع تُنجز بلوحة المفاتيح + قارئ الباركود فقط.
3. **لا أكثر من 3 ضغطات** لأي عملية يومية (بيع، بحث صنف، مرتجع، إقفال وردية).
4. **منع الخطأ قبل تصحيحه** (Nielsen #5): لا بيع منتهٍ، لا سالب، تأكيد قبل الترحيل، تحذير عند خصم كبير.
5. **الحالة واضحة دائماً** (Nielsen #1): اسم المستخدم، الوردية، حالة الطابعة، حالة الترخيص، آخر نسخة احتياطية — في شريط ثابت.
6. **لغة المستخدم لا لغة المبرمج** (Nielsen #2): "الدفعة" لا "Lot"، "المرتجع" لا "Reversal"، "إقفال اليوم" لا "Post".
7. **تدرّج التعقيد (Progressive Disclosure):** وضع بسيط افتراضي؛ المتقدم (دفعات يدوية، عملات) خلف زر "المزيد" أو بصلاحية.
8. **اتساق:** نفس أماكن الأزرار، نفس الألوان، نفس الاختصارات في كل الشاشات.
9. **قابلية الوصول** (WCAG 2.1 AA): تباين ≥ 4.5:1، حجم خط ≥ 14px (16px في POS)، أهداف لمس ≥ 44×44px، تنقل Tab منطقي، Focus مرئي.
10. **RTL أصلي** لا مُرقّع: الاتجاه، الأيقونات، الأرقام (عربية-هندية اختيارية)، التواريخ (ميلادي افتراضي + هجري اختياري).

## 3. بنية شاشة البيع (POS Layout)
```
┌─────────────────────────────────────────────────────────────────────┐
│ شريط الحالة: [المستخدم] [الوردية #12] [🖨️ متصلة] [🔒 مرخص] [💾 آخر نسخة: اليوم] │
├───────────────────────────────┬─────────────────────────────────────┤
│  🔍 بحث / باركود (F2) ────────│  🧾 الفاتورة #A-000456              │
│  [نتائج البحث فورية]          │  ┌──────┬────┬──────┬──────┬──────┐ │
│   • بنادول اكسترا  | علبة 1500│  │ الصنف│وحدة│ كمية │ سعر  │إجمالي│ │
│     متوفر: 24 علبة | ينتهي 03/27│  ├──────┼────┼──────┼──────┼──────┤ │
│     🔁 بدائل (3)              │  │ ...  │    │      │      │      │ │
│   • ...                       │  └──────┴────┴──────┴──────┴──────┘ │
│                               │  الإجمالي: 4,500   خصم: 0           │
│  [أصناف سريعة / الأكثر مبيعاً]  │  الصافي: 4,500 ريال (≈ 8.4 SAR)      │
│                               │  ─────────────────────────────────── │
│                               │  [F9 نقدي] [F10 آجل] [F8 خصم]        │
│                               │  [F4 مرتجع] [F7 تعليق] [Esc إلغاء]   │
└───────────────────────────────┴─────────────────────────────────────┘
```
- **تغيير الوحدة** (علبة/شريط/حبة) بزر دوّار على السطر أو مفتاح `U`.
- **الدفعة** تُختار تلقائياً (FEFO) وتظهر كمعلومة صغيرة؛ تغييرها يتطلب صلاحية.
- **المبلغ المستلم والباقي**: نافذة دفع بلوحة أرقام كبيرة؛ أزرار مبالغ سريعة (500/1000/5000).
- **الفاتورة المعلّقة** (Hold) لخدمة زبونين بالتناوب.

## 5. تدفقات رئيسية (Happy Paths) بعدد الضغطات
| التدفق | الخطوات | الضغطات |
|---|---|---|
| بيع نقدي بباركود | مسح → مسح → F9 → Enter (المبلغ المستلم) | 2 + مسح |
| بيع بالبحث | F2 → اكتب 3 أحرف → ↓ Enter → F9 → Enter | 5 |
| مرتجع | F4 → رقم الفاتورة/مسح → اختر السطر → Enter → تأكيد | 4 |
| استلام مشتريات | المشتريات → جديد → مورد → مسح صنف → كمية/انتهاء/تكلفة → ... → ترحيل | ~6 لكل صنف |
| إقفال وردية | F12 → عدّ النقد → تأكيد → طباعة | 3 |

## 6. سهولة التعلم (Learnability)
- **جولة تفاعلية** أول تشغيل (5 خطوات).
- **وضع تدريب (Sandbox)** ببيانات وهمية — لا يؤثر على الدفاتر.
- **تلميحات** على كل زر مع الاختصار.
- **فيديوهات 60–90 ثانية** لكل مهمة، مضمّنة في شاشة المساعدة (تعمل أوفلاين).
- **دليل مطبوع A4** صفحة واحدة لشاشة البيع يُلصق قرب الجهاز.
- هدف قابل للقياس: **NFR-USE-01** — موظف جديد يُتم أول بيع خلال ≤ 15 دقيقة.

## 7. الألوان والدلالات (Semantic Colors)
| الحالة | اللون | الاستخدام |
|---|---|---|
| طبيعي | رمادي/أزرق هادئ | — |
| تحذير | كهرماني | قارب الانتهاء (≤ alert_days)، مخزون منخفض |
| خطر | أحمر | منتهٍ، سالب، فشل طباعة |
| نجاح | أخضر | ترحيل ناجح، نسخة احتياطية |
| معلومة | أزرق | بدائل متاحة |
- لا نعتمد على اللون وحده (WCAG 1.4.1): أيقونة + نص.

## 8. الطباعة
- **فاتورة حرارية 80mm** (و58mm): شعار، اسم الصيدلية، رقم الفاتورة/التاريخ/الكاشير، الأصناف (اسم مختصر، كمية×سعر، إجمالي)، الخصم، الصافي بالعملتين، المدفوع/الباقي، رسالة شكر، QR اختياري (رابط/تحقق).
- **القالب HTML قابل للتعديل** من الإعدادات؛ يُحوَّل لصورة Raster → ESC/POS لضمان العربية [3].
- طباعة A4 للتقارير والفواتير الكبيرة.

## 9. الخط والطباعة الرقمية
- **Cairo** أو **IBM Plex Sans Arabic** أو **Tajawal** (مفتوحة، واضحة على الشاشات الصغيرة).
- أرقام: Latin (0-9) افتراضياً لسهولة الطباعة الحرارية؛ خيار عربي-هندي.

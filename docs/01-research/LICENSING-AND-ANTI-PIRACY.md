# R7 — الترخيص ومنع النسخ (Licensing & Anti-Piracy)

> **الهدف:** (طلب معين الصريح) منع نسخ البرنامج من صيدلية إلى أخرى، مع الحفاظ على عمل النظام بدون إنترنت، وربط الترخيص بالباقات.
> **المبدأ الواقعي:** لا يوجد حماية مطلقة لبرنامج يعمل على جهاز يملكه المستخدم. الهدف: **جعل النسخ أغلى من الشراء** مع تجربة سلسة للعميل الشرعي. [1]

---

## 1. نموذج التهديد (Threat Model)
| الهجوم | الاحتمال في اليمن | الدفاع |
|---|---|---|
| نسخ مجلد التثبيت + قاعدة البيانات لجهاز آخر | **عالٍ جداً** (الأكثر شيوعاً) | بصمة الجهاز في الترخيص الموقّع |
| مشاركة مفتاح ترخيص واحد بين عدة صيدليات | عالٍ | تفعيل عبر خادم يحسب عدد الأجهزة (حد = عدد المقاعد المشتراة) |
| تعديل الكود لتجاوز التحقق (`isLicensed = true`) | متوسط (يحتاج مهارة) | تحقق في عدة طبقات (API + DB + UI)، كود مبنّى/مضغوط، التحقق في الـ API وليس الواجهة فقط |
| تزوير ترخيص | منخفض (يحتاج المفتاح الخاص) | **Ed25519**: المفتاح الخاص على خادمنا فقط؛ العام في التطبيق لا يسمح بالتزوير |
| إرجاع ساعة النظام لتمديد الترخيص | متوسط | **Monotonic timestamp**: آخر وقت تحقق يُخزن؛ إن كان الوقت الحالي أقل → كشف تلاعب |
| إزالة قيد الصلاحية بتعديل قاعدة البيانات | متوسط | الترخيص مُوقّع كاملاً (Payload + Signature)؛ أي تعديل يفسد التوقيع |
| الاستمرار بعد إلغاء الترخيص (مثلاً عدم سداد) | — | إعادة تحقق دورية عند توفر إنترنت؛ فترة سماح قابلة للتهيئة |

## 2. التصميم المختار: Signed License Token + Hardware Binding + Offline Grace

### 2.1 المكونات
```
┌──────────────────────┐         ┌──────────────────────────────┐
│  License Server      │         │  Pharmacy Device              │
│  (خادمنا، Hono/Nest) │         │                              │
│  Private Key Ed25519 │ ──────► │  Public Key (في التطبيق)     │
│  DB: licenses,       │  token  │  license.token (موقّع)        │
│  activations         │         │  machine fingerprint          │
└──────────────────────┘         │  last_verified_at (ratchet)   │
                                 └──────────────────────────────┘
```

### 2.2 بنية التوكن (JWT-like، Ed25519 / EdDSA)
```json
{
  "lic": "LIC-2026-000123",            // رقم الترخيص
  "tenant": "uuid",                     // معرّف الصيدلية
  "mid": "sha256(hw-factors)[0:32]",    // بصمة الجهاز
  "plan": "pro",                        // الباقة
  "features": ["pos","inventory","accounting","multi_currency"],
  "seats": 2,                           // عدد الأجهزة المسموح
  "iat": 1762128000,
  "exp": 1793664000,                    // انتهاء الترخيص/الدعم
  "grace_days": 30,                     // فترة السماح بدون إنترنت بعد exp
  "recheck_days": 30                    // كل كم يوم يحاول إعادة التحقق
}
```
التوقيع: `base64url(payload) . base64url(Ed25519 signature)`.

### 2.3 بصمة الجهاز (Machine Fingerprint)
مرجّحة ومستقرة — مستوحاة من [1]:
| المصدر | Windows | Linux/mac | ملاحظة |
|---|---|---|---|
| Machine GUID | `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` | `/etc/machine-id` / `IOPlatformUUID` | المرساة الأساسية؛ ثابت عبر إعادة التشغيل، يتغير مع إعادة تثبيت Windows |
| Volume Serial للقرص C: | ✅ | — | ثانوي |
| CPU ID / Cores | ✅ | ✅ | ثانوي |
| MAC (غير العشوائي فقط) | ✅ | ✅ | يُستبعد إن كان Locally Administered bit = 1 |

- `mid = SHA256(sorted(factors).join("|"))[:32]`.
- **تسامح (Fuzzy match):** إن تغيّر عامل ثانوي واحد (مثل MAC) والمرساة ثابتة → مقبول؛ يمنع إزعاج العميل عند تغيير كرت شبكة.
- يُنفَّذ في Tauri (Rust) للديسكتوب، وفي Node sidecar للخادم المحلي.

### 2.4 تدفق التفعيل
1. العميل يثبّت البرنامج → يظهر "Machine Code" (mid).
2. **أونلاين:** يدخل مفتاح الترخيص → التطبيق يرسل `(license_key, mid)` للخادم → الخادم يتحقق من عدد التفعيلات ≤ seats → يصدر توكن موقّع → يُحفظ محلياً.
3. **أوفلاين (مهم لليمن):** يرسل الفني الـ Machine Code لنا (واتساب) → نولّد التوكن من لوحة الإدارة → يُنسخ كملف/نص للجهاز. **لا يحتاج إنترنت على جهاز الصيدلية إطلاقاً.**
4. عند كل تشغيل: تحقق محلي (توقيع + mid + exp + ratchet) خلال ميلي ثوانٍ.
5. إن توفر إنترنت: إعادة تحقق صامتة كل `recheck_days` → توكن مُجدَّد. فشل الشبكة ≠ إلغاء؛ رفض صريح (401/403) = إلغاء.

### 2.5 الباقات و Feature Flags
- `features[]` في التوكن = مصدر الحقيقة للـ Feature Flags.
- الـ API يتحقق عبر Guard: `@RequireFeature('multi_currency')`.
- الواجهة تخفي/تعطّل ما لا يملكه مع رسالة "ترقية".
- **الترقية = توكن جديد** بدون إعادة تثبيت. (يحقق قرار D-002: الأدمن يفتح الميزات لاحقاً).

### 2.6 انتهاء الترخيص — ماذا يحدث؟
- **ملكية دائمة (Perpetual):** `exp` = انتهاء **التحديثات والدعم** فقط. البرنامج يستمر بالعمل بالإصدار الحالي إلى الأبد (يحقق "بدون اشتراك"). التحديثات الجديدة تحتاج تجديد.
- **اشتراك:** بعد `exp + grace_days` → وضع **قراءة فقط** (يمكنه رؤية بياناته وتصديرها، لا بيع جديد). **لا نحجز بيانات العميل أبداً** (أخلاقياً وقانونياً).

### 2.7 طبقات الدفاع في الكود
| الطبقة | الآلية |
|---|---|
| API (NestJS) | `LicenseGuard` عالمي يرفض الطلبات بدون ترخيص صالح (ما عدا /license/*) |
| DB | جدول `license_state` + عمود `tenant_id` مرتبط بالترخيص؛ قاعدة بيانات منسوخة لجهاز آخر تحمل tenant لا يطابق التوكن |
| Desktop (Tauri/Rust) | التحقق قبل تشغيل الـ sidecar |
| UI | Feature gating (تجربة مستخدم فقط، ليس أمناً) |
| Build | كود مُصغّر/مبنّى؛ Rust binary للجزء الحساس |

## 3. البدائل المدروسة
| البديل | لماذا لا |
|---|---|
| Dongle USB | تكلفة، يُفقد، تجربة سيئة |
| تحقق أونلاين فقط | يناقض Offline-first |
| HMAC بمفتاح مشترك | المفتاح داخل التطبيق → يُستخرج ويُزوَّر |
| خدمات مثل Keygen.sh / LicenseSpring | ممتازة لكن اشتراك شهري بالدولار + اعتماد خارجي؛ نبني الحد الأدنى بأنفسنا (100–200 سطر) ونحتفظ بالخيار لاحقاً [2][3] |

## 4. الاعتبارات القانونية والأخلاقية
- عقد ترخيص (EULA) عربي واضح: عدد الأجهزة، مدة الدعم، ملكية البيانات للعميل.
- **تصدير البيانات متاح دائماً** حتى بعد انتهاء الترخيص.
- لا جمع بيانات مبيعات العميل على خوادمنا بدون موافقة صريحة (الخصوصية + الثقة).
